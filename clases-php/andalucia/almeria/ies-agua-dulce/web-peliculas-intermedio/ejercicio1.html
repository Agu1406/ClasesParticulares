Respuesta Ejercicio 1 Pregunta 1

1º- Modelo relacional: La información se organiza en entidades las cuales se representan mediante tablas.

Cada tabla se relaciona con las demás a través de su clave primaria y foráena. En nuestro caso las peliculas se organizan por filas. Cada fila contiene un grupo de datos al que llamamos registro y que representa una película concreta.

Cada columna de la tabla representa a su vez un atributo de la película (año, director, género, duración, argumento). Ejemplo de SGBD es MySQL

2º- Modelo no relacional: No sigue el modelo tradicional relacional de filas y columnas. Su estructura es mucho más flexible y está pensando para almacenar grandes volúmnes de datos con estructuras muy variables.

Están pensados para almacenar una variedad de datos en forma de documentos (JSON), como un diccionario usando pares clave-valor o datos por columnas en vez de por filas

En nuestro caso, cada película está recogida en vez de en tablas dividas por filas y columnas, en un único documento donde cada clave seria: duracion, genero, director y el valor el dato correspondiente

Aunque pueden usarlo, su legunje de consulta principal no es SQL, sino otros más personalizados Ejemplo de SGBD es MongoDB

3º- Modelo oriendato a objetos: Al igual que ocurre en la programación orientada a objetos, la información se organiza en objetos que contiene tanto atributos como métodos.

Es ideal cuando estamos usandos lenguajes de POO como java. Permite almacenar estructuras de datos complejas como videos o gráficos.

En nuestro caso cada película podría ser un objeto con los atributos: director, año, duración, género. Y si quisiéramos también podriamos crear un objeto llamado actores que se relacione con las películas a través de un ArrayList Ejemplo de SGBD es db4o

Respuesta Ejercicio 1 Pregunta 2

Para el caso concreto de las películas el SGBD elegido sería el entidad-relacional por varias razones

1. Es el sistema de base de datos más extendido de la web con desarrollo PHP
2. Tiene una gran facilidad de uso y un alto rendimiento
3. Se adapta perfectamente a una estructura de datos no compleja como es nuestro caso
4. Cuenta con librerias fuertes como PDO y MySQLi que permite la conexión segura
5. Permite realizar consultas complejas con SQL y establecer relaciones entre las películas
6. Amplia comunidad, documentación y escalable.

No usamos NoSQL porque nuestra base de datos de películas tiene una estructura simple
Y no usamos BD orientadas a objetos porque son menos comunes en PHP y porque no aporta mejora para nuestra base de datos relacional simple y estructurada

Respuesta Ejercicio 1 Pregunta 4

Existe dos formas de acceder a MariaDB y MySQL

MySQLi (MySQL Improved): Extensión de PHP diseñada para interactuar con bases de datos MySQL y MariaDb. Se caracteriza por: 1.Uso de una intefaz gráfica mejorada en comparación con la antigua extensión MySQL
2.Soporta tanto tanto el enfoque procedural como el orientado a objetos
3.Permite realizar conexiones, ejectura consultar y gestionar los resultados
4.Es mucho más segura al permitir el uso de declariones preparadas

PDO (PHP Data Objects): Extensión de PHP diseñada para interactuar con bases a través de una interfaz unificada. Se caracteriza por: 1.Permite trabajar, además de MariaDB y MySQL con una gran cantidad de bases de datos como: ostgreSQL, SQLite, SQL Server, Oracle Database, entre otras.
2.Su interfaz unificada le permite cambiar facilmente entre los distintos SGBD
3.Permite el manejo de excepciones facilitando la gestión y depuración de errores.
4.Es adecuado para aquellos proyectos que necesiten cambiar de base de datos o busquen un punto de vista más profesional.

Respuesta Ejercicio 1 Pregunta 5

1. Tipo de SBGD:
Cassandra: No relacional, por columnas de código abierto
MySQL: Relacional de código abierto.

2. Estructura de datos:
Cassandra: Columnas distribuidas, donde cada tabla puede tener distinto número de columnas
MySQL: Filas y columnas con relaciones entre las tablas

3. Lenguaje de consulta:
Cassandra: Uno suyo propio, el CQL
MySQL: El lenguaje estándar SQL

4. Integridad de datos:
Cassandra: Consistencia eventual, ACID parcial. Los datos replicados convergerán al mismo valor pero no al mismo momento instantáneo
MySQL:ACID Atomicidad, Coherencia, Aislamiento y Durabilidad.

5. Escalabilidad:
Cassandra: Tiene una escabilidad horizontal, añadiendo nuevos nodos al cluster.
MySQL: La escabilidad se puede mejorar si se mejora el rendimiento del servidor

Ventajas
Cassandra: Es muy escalable, tolerante a fallos, alta disponibilidad y manejo de un gran volumen de datos. MySQL: Modelo muy conodio, soportado por un gran número de hosting, soporta relaciones complejas, transacciones completas, integridad de gran comunidad

Desventajas
Cassandra: Resulta dificil implementar consultas que sean complejas y las relaciones entre datos.Tampoco soporta transacciones completas ACID. Al ser menos comun requiero de aprendizaje especifico y librerias propias.
MySQL: Si el volumen es alto la escalabilidad limitada. Menos flexible si la estructura de datos cambia con frecuencia. No es adecuado para tener varias bases de datos en distintos puntos geográficos
